# 方針メモ（技術構成・データ・ログイン）

要件定義書（`docs/requirements.md`）の未決事項のうち、決まったことと検討中のことをまとめる。
機密情報（認証情報・URL・アカウント名など）はこのファイルに書かない。

## 1. 全体構成（決定）

スプシの列定義は `docs/sheets.md`、GAS の API は `docs/api.md` を参照。

| 項目 | 決定内容 |
|---|---|
| 参加者向け画面 | GitHub Pages で公開（Next.js の静的書き出し）。独自ドメイン cbquiz.archive.fsif.jp の直下。ゲストは誰でも利用可 |
| バックエンド | Google Apps Script（GAS）の Web アプリ |
| データベース | Google スプレッドシート |
| ログイン | Discord ログイン（Cosmo Base の Discord サーバー参加者のみ） |
| 管理画面 | 既存の Quiz Manager（GAS）に追加。参加者向けサイトには作らない。操作できる人の制限などは Quiz Manager 側の開発で扱う |
| GAS のコード管理 | GAS エディタのみ。団体の Google アカウントで所有し、デプロイの版にメモを付けて管理。GitHub には上げない |
| テスト環境 | 本番とテストでスプシ・GAS を分けない |
| GitHub リポジトリ | 公開（GitHub Pages を無料プランで使うため）。秘密情報はコードに入れない |
| Google アカウント | 通常の Google アカウント（Workspace ではない）。GAS の上限は通常アカウントの値で見積もる |

### GitHub Pages 対応（決定：案1）
- `next.config.mjs` に静的書き出し（`output: 'export'`）を設定する。公開パス（`basePath`）は環境変数 `PAGES_BASE_PATH` で指定でき、独自ドメインでは空にする。
- ID を含むページはクエリパラメータで ID を渡す形に変える。
  - 例：`/attempts?id=…`、`/attempts/result?id=…`、`/questions/detail?id=…`、`/notices/detail?id=…`
- GitHub Actions でビルドして Pages に公開する。

## 2. 問題データ（決定）

- 分野は7つ：天文／宇宙開発／宇宙ビジネス／宇宙探査／歴史／宇宙基礎／宇宙政策。
- 元のクイズデータから、必要な情報だけを Archive 用スプシに移行し、問題IDを付ける（列の対応は `docs/sheets.md`）。
- 元スプシには毎朝6時に「当日の問題」と「前日の SNS 回答数」が反映される。日次の取り込みでは、出題日が前日と当日の行だけを読む。前々日以前の行は変わらないため読まない。
- 出題・表示は Archive 用スプシだけを使う。
- **サイトへの公開は出題日の翌日から**（SNS の回答期間中にサイトで正解・解説が見られないようにするため）。
- 問題文の先頭の「では、」などの接続詞（SNS 投稿文の前置きを受けたもの）は、取り込み時に取り除く。
- 出題日と出題した媒体を、画面に小さく表示する。
- **時事問題**：SNS では「今日・本日・今年」のように出題日を前提にした書き方がある。取り込みで、出題日をもとにした日付（例：「2026年11月23日」「2026年」）に書き換え、import_issues に記録する。「予定・現在・最近」などを含む問題と書き換えた問題は時事問題（questions の `time_sensitive`）にし、サイトの問題・回答中・結果に「○年○月○日の出題時点の内容です」と出す。運営は Quiz Manager で外せる。
- 新しい問題の見積もり（`difficulty_prior`）は、Quiz Manager が KPI シートの「難易度（自動）」に書いた難易度（初級・中級・上級）を取り込む。
- 複数の媒体に同じ問題を出していたのは超初期のみ。媒体ごとの SNS 回答数は合計して使う。
- 回答の書き方がそろっていないため、正解は「番号があれば番号、なければ選択肢の文字と照合、決まらなければ人が確認」で決める。
- 問題の変更・修正は Quiz Manager の管理画面から行う。修正すると新しい版を追加し、古い版は消さない（回答記録は当時の版にひも付ける）。
  - Quiz Manager の「過去問サイト」の画面から直す。Quiz Manager の GAS が権限を確かめ、Archive の GAS に合言葉付きで中継する（`docs/api.md` 6.5）。
  - 正解・選択肢を変えたときは正答率を数え直す（新しい回答が10件たまるまでは、それまでの表示値を引き継ぐ）。誤字の修正などは、担当者が選べば数え直さない。

## 3. スプレッドシートの構成（決定）

Archive 用のスプレッドシートは**1つ**にし、次の4つのグループをタブ（シート）として作る（タブ名・列は `docs/sheets.md`）。

- 個人データも同じファイルに入るため、ファイルを共有するのは管理者に絞る。
- 1つのスプレッドシートに入るセルは1,000万個まで。上限に近づいたら、回答の記録など増え続けるタブを別ファイルへ移す。

| グループ | 主な中身 | 見られる人 |
|---|---|---|
| ① 問題 | 問題ID、版、問題文、選択肢、正解、解説、参考文献、分野、SNS正答率、公開状態 | 運営 |
| ② 統計 | 問題・版ごとの基本／復習の回答数・正解数（ゲスト／ログイン利用者の区別つき） | 運営 |
| ③ 個人データ | 利用者（識別用の値・レベル・合格数・星）、回の記録、回答、セット履歴 | 管理者のみ |
| ④ 運営 | お知らせ・訂正、誤り報告、設定値（合格点・判定件数など） | 運営 |

## 4. 正答率と難易度（決定）

- 要件どおりとする。有効な基本回答が10件に達するまでは SNS 正答率を表示し、10件に達したらサイトの基本正答率に切り替える（FR-20〜22）。
- 問題難易度も同じく、10件未満は SNS 正答率から、10件以上はサイトの基本正答率から判定する（境界：50%超＝初級、30%超〜50%＝中級、10%超〜30%＝上級、0〜10%＝専門家）。
- サイトでの回答データは、基本／復習、ゲスト／ログイン利用者の区別をつけて記録する。

### 難易度の推定（決定。サイトの基本回答が10件たまるまで）
- SNS のうち、数字として当てになるのは X だけ（Discord・Instagram・マイコミュは回答が1〜2件で、ほぼ意味を持たない）。X は回答者の正答率が高い（約80%）ため、X 用の物差しで判定する。
- 運営が付けた見積もり（questions の `difficulty_prior`。問題文と選択肢から、要る知識と誤答のもっともらしさで4段階）を出発点にし、X の回答で寄せる。
  - 出発点：見積もりを X の物差しの正答率（初級 90%・中級 78%・上級 62%・専門家 45%）に置き換え、8人分の重みで入れる。
  - X の回答：正解数・回答数を足す。前後14日に X へ出した問題の回答数の中央値より少なかった分は、その半分を不正解とみなす（「回答が少ない＝難しい」。ふつうの半分まで）。多かった分（時事で伸びた分）は数えない。回答0件はデータなし。
  - 境目（X の物差し）：82%・70%・55%。X の回答が3件未満なら、見積もりから1段までしか動かさない。
  - 値は settings タブで変えられる（`est_prior_weight`・`est_nonresponse`・`est_x_min_answers`・`est_cut_beginner`・`est_cut_intermediate`・`est_cut_advanced`）。
- 参加者に見せる正答率は今までどおり（10件未満は SNS、なければ未集計）。変わるのは難易度だけ。
- サイトの基本回答が10件以上になったら、サイトの正答率で判定する（今までどおり）。サイトの境目は、回答がたまったら KPI を見て決め直す。
- 見積もりがなく X の回答もない問題（新しく取り込んだ問題など）は、今までどおり SNS → 不明。

### SNS 正答率がない問題（決定）
- 基本回答が10件に達するまで、正答率は「未集計」、問題難易度は「不明」と表示する（0% や初級として補わない）。
- 難易度の絞り込み（一覧・練習）に「不明」は加えない。

- テストでは、難易度「不明」の問題は専門家の星のテストの「全難易度ランダム」枠だけで使う。昇格テスト（中級・上級・専門家）には出題しない。

## 5. ログイン（Discord）

### 決定
- Cosmo Base の Discord サーバー参加者だけがログインできる。参加しているかはログインのたびに確認する。
- Discord から受け取る情報は最小限にし、メールアドレスは受け取らない。
- **表示名はスプシに保存しない。** ログイン時に GAS からブラウザへ返し、その端末の中だけで表示する（Discord で名前を変えた場合、表示は次のログイン時に更新される）。
- GAS のログ出力に表示名などの個人情報を書き出さない。
- Discord 連携用の秘密の鍵は GAS のスクリプトプロパティに置き、スプシや GitHub に書かない。
- ログイン後はサイト独自のログイン用トークンを発行し、スプシには元に戻せない形（ハッシュ）で有効期限つきで保存する。有効期限は30日。

### 利用者の識別方法（決定）
- Discord のユーザーIDは保存しない。ユーザーIDと、GAS だけが持つ秘密の鍵から作った元に戻せない値を、利用者の識別用の値として保存する。
- 注意点
  - 秘密の鍵はスクリプトプロパティだけに置く。スプシと一緒に漏れると、特定の Discord アカウントが利用者かどうかを総当たりで調べられる。
  - 秘密の鍵を変えたり失ったりすると全員が別人扱いになるため、団体の管理下で安全に控えておく。

### Discord サーバーを抜けた人（決定）
- 次のログインのときに確認し、`NOT_MEMBER` で断る。抜ける前に発行したログイン状態は、期限（最長30日）まで使える。
- 抜けたと分かったら、その人の記録を匿名の値（`anon-…`）に置き換える。どの Discord アカウントとも結び付かなくなり、統計としてだけ残る。元に戻せない。
- もう一度参加してログインした場合は、新しい利用者として始まる。

### 記録の保存期間と削除の依頼（決定）
- 記録は期間を決めずに保存する。
- 本人から依頼があったとき（Discord で受け付ける）は、消すのではなく、上と同じく匿名の値に置き換えて統計として残す。スプシのメニュー「Archive → 利用者の記録を匿名化」から、依頼した人の Discord のユーザーIDを入れて実行する（IDは保存もログ出力もしない）。

### 運用（決定）
- 週1回、スプシをバックアップ用のフォルダにコピーする（スプシに付いている GAS もいっしょにコピーされる）。新しい8つだけ残す。フォルダを共有するのは管理者だけ。
- 期限が切れて7日たったログイン記録（sessions）は、毎朝の取り込みのあとに消す。

## 6. 設計時の注意（方針）

- **正解・解説を事前にブラウザへ送らない。** GitHub Pages のファイルは誰でも見られるため、正解・解説は回の終了時（単問は回答送信時）に GAS から返す。
- **採点・合否・認定・統計の更新は GAS で行う。** ブラウザから送られた得点は信用しない。
- 期限は開始時に GAS が決め、終了時刻の判定も GAS で行う（端末の時計は信用しない）。
- 終了処理はロック機能で同時書き込みを防ぎ、回ごとに一度だけ反映する。
- GAS は応答が1〜2秒かかることがあり、同時実行数や1日の実行回数にも上限がある。回答の保存はまとめて送る、問題一覧はキャッシュする、統計は集計用シートに足し込む、などで負荷を抑える。
- GAS の Web API はヘッダーを自由に設定できないため、ログイン用トークンは送信内容（本文）に入れて送る。
- テスト環境を分けないため、テストで作った回答が本番の統計に混ざらないよう、テスト用の回答を見分けて除外できるようにしておく。

| 07 再判定 | 基本回答が10件に達したら判定し、以後 `rejudge_interval`（初期10件）増えるごとに判定し直す。間隔を変えると、次の回答から新しい間隔で数える。終了処理はロックの中で行い、二重に数えない。例外として、運営は Quiz Manager から問題の難易度を手で固定できる（questions の `difficulty_override`）。固定するとサイトの表示と出題はその難易度を使い、正答率の表示と統計・自動の判定は続ける。外すと自動に戻る | — |
| 08 分析 | 集計は Archive の GAS が毎朝作り、KPI ダッシュボードに表示する（`docs/kpi-archive.md`）。期間は日本時間の日付（回は開始日、終了の数は終えた日）。放置は「期限切れのまま開かれていない、または時間制限なしで開始から7日」 | ダッシュボードの画面（別のセッションで作る） |
| 09 告知と報告 | 訂正はお知らせ（訂正）で出す。過去の採点・合格・レベル・星はさかのぼって直さない。誤り報告は Quiz Manager で受けて状態を管理し、報告だけでは問題を止めない | お知らせの既読の管理（今は公開期間中ずっと出す） |
| 10 保存と削除 | 期間を決めずに保存。抜けた人・本人の依頼は匿名化して統計として残す（5章）。週1回のバックアップ、ログイン記録の削除（運用） | — |
