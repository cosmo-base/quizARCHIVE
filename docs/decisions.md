# 方針メモ（技術構成・データ・ログイン）

要件定義書（`docs/requirements.md`）の未決事項のうち、決まったことと検討中のことをまとめる。
機密情報（認証情報・URL・アカウント名など）はこのファイルに書かない。

## 1. 全体構成（決定）

| 項目 | 決定内容 |
|---|---|
| 参加者向け画面 | GitHub Pages で公開（Next.js の静的書き出し）。ゲストは誰でも利用可 |
| バックエンド | Google Apps Script（GAS）の Web アプリ |
| データベース | Google スプレッドシート |
| ログイン | Discord ログイン（Cosmo Base の Discord サーバー参加者のみ） |
| 管理画面 | 既存の Quiz Manager に追加（参加者向けサイトには作らない） |
| GAS のコード管理 | GAS エディタのみ。団体の Google アカウントで所有し、デプロイの版にメモを付けて管理。GitHub には上げない |
| テスト環境 | 本番とテストでスプシ・GAS を分けない |

### GitHub Pages 対応（決定：案1）
- `next.config.mjs` に静的書き出し（`output: 'export'`）と `basePath` を設定する。
- ID を含むページはクエリパラメータで ID を渡す形に変える。
  - 例：`/attempts?id=…`、`/attempts/result?id=…`、`/questions/detail?id=…`、`/notices/detail?id=…`
- GitHub Actions でビルドして Pages に公開する。

## 2. 問題データ（決定）

- 元のクイズデータから、必要な情報だけを Archive 用スプシに**一度だけ移行**し、問題IDを付ける。
- 移行後は元スプシを読まない。出題・表示は Archive 用スプシだけを使う。
- 問題の変更・修正は Quiz Manager の管理画面から行う。修正すると新しい版を追加し、古い版は消さない（回答記録は当時の版にひも付ける）。

## 3. スプレッドシートの分け方（案）

アクセス権を分けやすく、セル数の上限（1スプレッドシートあたり1,000万セル）に当たりにくいように、ファイルごと分ける。

| スプレッドシート | 主な中身 | 見られる人 |
|---|---|---|
| ① 問題 | 問題ID、版、問題文、選択肢、正解、解説、参考文献、分野、SNS正答率、公開状態 | 運営 |
| ② 統計 | 問題・版ごとの基本／復習の回答数・正解数（ゲスト／ログイン利用者の区別つき） | 運営 |
| ③ 個人データ | 利用者（識別用の値・レベル・合格数・星）、回の記録、回答、セット履歴 | 管理者のみ |
| ④ 運営 | お知らせ・訂正、誤り報告、設定値（合格点・判定件数など） | 運営 |

## 4. 正答率と難易度（決定）

- 参加者に見せる正答率は、当面 **SNS 正答率だけ**とする。
- 問題難易度も SNS 正答率から判定する（境界は要件どおり：50%超＝初級、30%超〜50%＝中級、10%超〜30%＝上級、0〜10%＝専門家）。
- サイトでの回答データ（基本／復習、ゲスト／ログイン利用者の区別つき）は記録しておき、データが集まった段階でサイトの正答率への切り替えを検討する。
- 要件の「基本回答10件でサイトの正答率に切り替え」（FR-20〜22）は、それまで保留とする。

### 検討中
- SNS 正答率がない問題の扱い（「未集計」と表示し、初級扱いとするか）。

## 5. ログイン（Discord）

### 決定
- Cosmo Base の Discord サーバー参加者だけがログインできる。参加しているかはログインのたびに確認する。
- Discord から受け取る情報は最小限にし、メールアドレスは受け取らない。
- **表示名はスプシに保存しない。** ログイン時に GAS からブラウザへ返し、その端末の中だけで表示する（Discord で名前を変えた場合、表示は次のログイン時に更新される）。
- GAS のログ出力に表示名などの個人情報を書き出さない。
- Discord 連携用の秘密の鍵は GAS のスクリプトプロパティに置き、スプシや GitHub に書かない。
- ログイン後はサイト独自のログイン用トークンを発行し、スプシには元に戻せない形（ハッシュ）で有効期限つきで保存する。

### 案（確認待ち）：利用者の識別方法
- Discord のユーザーIDは保存しない。ユーザーIDと、GAS だけが持つ秘密の鍵から作った元に戻せない値を、利用者の識別用の値として保存する。
- 注意点
  - 秘密の鍵はスクリプトプロパティだけに置く。スプシと一緒に漏れると、特定の Discord アカウントが利用者かどうかを総当たりで調べられる。
  - 秘密の鍵を変えたり失ったりすると全員が別人扱いになるため、団体の管理下で安全に控えておく。

### 検討中
- Discord サーバーを抜けた人の扱い（ログイン不可とするか、実績は残すか）。

## 6. 設計時の注意（方針）

- **正解・解説を事前にブラウザへ送らない。** GitHub Pages のファイルは誰でも見られるため、正解・解説は回の終了時（単問は回答送信時）に GAS から返す。
- **採点・合否・認定・統計の更新は GAS で行う。** ブラウザから送られた得点は信用しない。
- 期限は開始時に GAS が決め、終了時刻の判定も GAS で行う（端末の時計は信用しない）。
- 終了処理はロック機能で同時書き込みを防ぎ、回ごとに一度だけ反映する。
- GAS は応答が1〜2秒かかることがあり、同時実行数や1日の実行回数にも上限がある。回答の保存はまとめて送る、問題一覧はキャッシュする、統計は集計用シートに足し込む、などで負荷を抑える。
- GAS の Web API はヘッダーを自由に設定できないため、ログイン用トークンは送信内容（本文）に入れて送る。
- テスト環境を分けないため、テストで作った回答が本番の統計に混ざらないよう、テスト用の回答を見分けて除外できるようにしておく。
