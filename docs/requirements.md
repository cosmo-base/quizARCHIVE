# Cosmo Base 毎日宇宙クイズ 過去問練習サイト 要件定義書

版：1.0／作成日：2026年11月7日／状態：決定方針を反映したレビュー用初版

本書は企画段階での合意を機能・データ・受入条件に整理したもの。認証方式、保存先、外部連携方式等は未選定。詳細設計上の推奨値・未決事項は決定事項と区別する。以前の共有資料や試作と矛盾する場合、本書の最新方針を優先する。

## 1. 目的・対象・範囲

### 1.1 目的
作成済みの200問以上の宇宙クイズを活用し、コミュニティ参加者が過去問の検索、条件指定の練習、昇格テスト、解説による振り返りを行えるサイトを提供する。運営は回答量・正答率・無回答・平均点などを収集し、問題難易度の自動判定と利用状況の分析に利用する。

### 1.2 対象者・権限
| 区分 | 利用範囲 |
|---|---|
| ゲスト | 一覧、検索、単問回答、練習、全レベルのテスト、今回の結果・解説 |
| ログイン利用者 | 上記に加え学習履歴・個人レベル・星。認定テストは自分の次の昇格段階のみ。専門家は専門家テスト |
| 運営 | 外部の管理機能を通じて設定・問題版・お知らせ・報告・統計を扱う。参加者の私的な履歴は一般公開しない |

ログインはサービス利用の必須条件ではない。既存参加者ページには認証機能がないため新設方法を技術相談する。コミュニティ参加資格の確認方法は未決であり、ログインと参加資格を同義にしない。

### 1.3 範囲
- 対象：参加者向けUI、出題・回答・採点、認定、基本／復習統計、保存、版との紐付け、外部管理機能との連携要件。
- 管理者サイトのUI制作は対象外。別サイトまたは既存Quiz Manager（クイズ自動投稿ツール）への追加を想定。
- ランキング・他者への成績公開は対象外。将来要望が多ければ検討。
- 最初にV0でモックデータによるUI/UXを制作し、認証・永続保存・実データ連携を後続実装する。

## 2. 用語・集計区分
| 用語 | 定義 |
|---|---|
| 個人レベル | 初級・中級・上級・専門家。認定テストで自動昇格。降格なし |
| 問題難易度 | 問題ごとの基本正答率に基づく初級・中級・上級・専門家 |
| 新規生成 | 設定条件からその回の問題セットを生成する通常練習・テスト。個々の問題は既出でもよい |
| 復習 | 履歴にある問題セットを練習として解き直すこと。基本集計・認定から除外 |
| 基本正答率 | 有効な通常回答の正解数÷選択済み回答数。初回限定ではない |
| 復習正答率 | 有効な復習回答の正解数÷選択済み復習回答数 |
| SNS正答率 | 元データとして提供されたSNSの回答実績 |
| 得点率 | 正解数÷出題総数。テストでは常に40問を分母とする |
| 回答済み正答率 | その回の正解数÷選択済み問題数。未回答を除外 |
| 問題セット | 順序を無視した問題IDの集合。並び順だけ違っても同一 |
| 有効回答 | 集計対象の回で終了確定した選択済み最終回答。二重送信・未回答等を除く |

## 4. 一覧・単問回答

### FR-01 一覧
- 問題文を検索できる。検索文字の空白処理等は詳細設計。
- 分野・難易度を絞り込める。分野は複数選択、同一軸内はOR、異なる軸間はANDを推奨。
- 正答率の昇順・降順を用意する。未集計の並び位置は詳細設計。
- 問題文・分野・難易度・表示用正答率を表示し、正解は隠す。
- 正答率は1つのみ。参加者向けにSNS／サイトという由来を表示しない。
- 該当0件、読み込み中、取得失敗、ページ切替を表現する。
- 絞り込みを練習設定に引き継ぐ導線を設ける想定。

### FR-02 単問
- 選択して回答ボタンを押すと最終回答を確定し、その後に正解・解説を表示。
- 解説表示前に確定した回答は基本集計対象。解説を先に閲覧した後の回答は基本集計に加えない。
- 同一回答イベントの再送は一度だけ集計する。意図的な再回答は新しいイベントとして識別するが、解説閲覧済みの扱いに従う。
- 回答なしで解説だけ読む経路は設ける案。採否・既読判定の持続範囲は未決事項。
- 参考文献、問題・解説の誤り報告を用意する。

## 5. 練習・復習

### FR-03 通常練習
- 問題数、分野、問題難易度を選択しランダム出題。
- 候補件数を表示し、重複なしで生成できる件数のみ開始可能とする。
- 終了ボタンを設け、未回答があっても終了可能。
- 終了まで回答変更可能。正誤・正解・解説は最後にまとめて表示。
- 任意の時間制限設定を設ける方針。選択肢・無制限の初期値・練習時間切れの集計詳細はTBD-01。
- 個人レベルによる難易度制限は設けず自由に練習できる。

### FR-04 練習目安
| 個人レベル | 1問 | 40問換算 |
|---|---:|---:|
| 初級 | 120秒 | 80分 |
| 中級 | 90秒 | 60分 |
| 上級 | 60秒 | 40分 |
| 専門家 | 40秒 | 26分40秒 |
これは個人レベルに応じた目安であり強制終了時間ではない。ゲストの目安表示基準はTBD-01。認定テストの時間は全員60分。

### FR-05 履歴からの復習
- 過去の練習・テストを練習として解き直せる。
- 「この問題を練習し直す」と「同じ条件で新しく挑戦」を区別する。
- 前者は同じセットの復習、後者は現在の問題群から新規生成。
- 復習は昇格・星の対象外。基本正答率に加えず、運営向けの復習正答率として保存・集計する。
- 復習はセット重複禁止の例外。
- 問題修正・出題停止がある場合に旧版／現行版のどちらを復習に使うかはTBD-02。履歴の当時の内容と混同させない。

## 6. テスト・認定

### FR-06 共通条件
- 出題数40問、制限時間3600秒。正解1点、不正解・未回答0点。
- 32点以上（80％以上）で1回合格。31点以下は不合格。
- 全問回答は不要。手動終了でも時間切れでも同じ32点基準を使う。
- 外部検索・資料参照を許容する。離席・タブ切替を理由に失格にしない。
- 再受験の回数・間隔に制限なし。ただしセット重複防止は適用。

### FR-07 基準構成
| テスト種別 | 初級 | 中級 | 上級 | 専門家 | 全難易度ランダム |
|---|---:|---:|---:|---:|---:|
| 中級昇格 | 25 | 10 | 5 | 0 | 0 |
| 上級昇格 | 0 | 25 | 10 | 5 | 0 |
| 専門家昇格 | 0 | 0 | 25 | 15 | 0 |
| 専門家の星 | 0 | 0 | 0 | 30 | 10 |
全難易度ランダム枠は専門家も含む。固定30問とは問題IDを重複させない。

### FR-08 個人レベル
- 初回は全員初級。ログイン利用者の当該段階の合格が累計3回になれば自動昇格。
- 不合格で合格回数を減らさない。昇格後は次段階の合格を0から数える。
- 初級は中級昇格、中級は上級昇格、上級は専門家昇格、専門家は星テストのみ認定対象として受験できる。
- ゲストは全種別受験可能だが合格・昇格・星は認定しない。後のログインによる認定引き継ぎも不可。
- 降格なし。問題難易度変更で過去合格を取り消さない。
- 同一回の終了再送で合格や星を二重加算しない。

### FR-09 専門家の星
専門家到達後の専門家テスト累計合格を使う。昇格までの合格は星計算に流用しない。
| 累計合格 | 表示 |
|---:|---|
| 0〜2 | 星なし |
| 3〜5 | ☆ |
| 6〜8 | ☆☆ |
| 9〜11 | ☆☆☆ |
| 12〜14 | ☆☆☆☆ |
| 15〜17 | ☆☆☆☆☆ |
| 18〜20 | ★☆☆☆☆ |
| 21〜23 | ★★☆☆☆ |
| 24〜26 | ★★★☆☆ |
| 27〜29 | ★★★★☆ |
| 30〜32 | ★★★★★ |
| 33〜35 | ★＋6 |
| 36〜38 | ★＋7 |
以降合格3回ごとに黒星相当数を1増加。次の表示まであと何回合格が必要かを示す。
計算例：k=floor(合格数/3)。k≤5なら白星k個。6≤k≤10なら黒星(k−5)個と白星(10−k)個。k≥11なら「★＋(k−5)」。

## 7. 出題・重複防止

### FR-10 分野・難易度調整
1. 公開中で有効な問題版を候補とする。
2. テストでは分野の均等配分を難易度構成より優先する。
3. 基準難易度の候補が不足すれば1段階下の難易度を活用。
4. 特定分野の不足を補うため必要なら難易度を上げ、他枠と調整して基準構成に近づける。
5. 同じ回には同じ問題IDを重複させない。基準構成と実際の構成を双方保存する。
6. 代替があっても32／40点の合格条件は維持。

分野数をGとした均等配分の基本案は各floor(40/G)問、余りを分野へ配分。候補不足時の分野間再配分、下位も不足した場合の再帰補充、最上位等の行き止まり、均等性の許容差はTBD-03。制約を満たせないまま同一問題を重複させたり、無断で少ない問題数の認定テストを開始しない。

### FR-11 セット判定
- 問題IDをソートした正規化集合等で同一性を自動判定する。順序・時間設定の違いだけでは別セットにしない。
- 別の組み合わせを作れる設定では、その利用者の直近5回以内と同じセットを禁止。
- 日付が変わると重複防止用の履歴だけリセット。学習履歴・成績は削除しない。日界は日本時間0時を設計前提とする。
- 設定上セットが1つしか存在しない場合は重複を許可。履歴復習も例外。
- ログインはアカウント、ゲストはブラウザ単位で判定する案。匿名の別端末・保存削除後の同一性は保証しない。
- 履歴を開始時／終了時のどちらで記録するか、練習とテストの履歴共有範囲、候補2〜5セットが全て禁止に入る場合はTBD-04。勝手に重複制限を緩和しない。

## 8. 出題中の状態・時間・認証

### FR-12 回答操作
- 選択肢選択、前後移動、問題番号移動、回答変更ができる。
- 回答済み・未回答・現在位置を文字・形でも識別可能にする。
- 終了確認では回答数・未回答数を示す。終了確定まで選択は変更可能。
- 正解・解説は終了前に表示しない。サーバー側でも認定・集計を検証する。

### FR-13 時間・途中保存
- テスト実開始で開始時刻・期限を確定。案内モーダル中は開始しない。
- 再読み込み・離席・通信切断で時計を止めない。再開時も元の期限を使う。
- 選択内容・現在位置等を途中保存し、保存中・保存済み・未同期／失敗を区別する。
- 期限到達で回答を自動確定。選択済みを採点し、32点以上なら合格。
- 切断中の未同期回答の採用、サーバー期限判定、遅延送信の許容、未復帰時の自動終了はTBD-05。端末時刻を変えただけで延長できる設計にしない。

### FR-14 認証
- 練習・テストの回答中はログイン／ログアウトのUI操作を不可にする。
- ゲストのテスト前には毎回ログイン案内を表示。ログインボタンと×を用意。
- ゲスト続行には×で明示的に閉じる操作が必要。背景クリックで閉じない。キーボード・支援技術でも閉じるボタンを操作できること。
- 「ログインすると実績保存できる」「ゲストの結果は後でログインしても認定対象にならない」を表示。
- 開始時のアカウント・認定資格を固定。他アカウントへ結果を移さない。
- 別タブの認証変更・認証期限切れはUI禁止だけでは防げないためTBD-06で扱いを決める。

### FR-15 終了状態
| 状態 | 意味 | 集計 |
|---|---|---|
| in_progress | 回答中。切断による中断を含む | まだ確定集計しない |
| completed | 手動終了確定 | 選択済み回答を反映 |
| timed_out | テスト期限到達による自動終了 | 選択済み回答を反映 |
| invalidated | 技術的不整合等で集計無効 | 採用条件・運営手続きは詳細設計 |

手動終了時の全問回答／未回答ありは終了理由・回答数で区別して分析可能にする。タブ閉じのみで直ちに終了確定しない。時間のない練習の未復帰回の扱いはTBD-05。

## 9. 採点・結果・履歴

### FR-16 採点
- 出題時点の問題版・正解を使用。回答中に問題修正・難易度変更を反映しない。
- テスト得点＝正解数、得点率＝正解数/40。回答済み正答率＝正解数/回答数。
- 0回答なら得点0、得点率0％、回答済み正答率は算出不可（0％と混同しない）。
- 例：32回答32正解8無回答→32/40点、80％で合格、回答済み正答率100％。
- 時間切れも同じ条件。ゲストには結果としての合否を表示しても認定実績へは加えない。

### FR-17 結果
- 得点、正解・不正解・未回答数、回答済み正答率、所要時間、終了状態、該当時の合否を表示。
- ログイン認定対象では合格進捗・昇格・星更新を表示。
- 未回答を含む出題全問について、問題文、選択肢、最終回答、正解、正誤、解説、参考文献を表示。
- 誤り報告、履歴、復習、新規挑戦への導線を設ける。

### FR-18 個人履歴・公開範囲
- ログイン利用者に日時・設定・問題セット・問題版・最終回答・正誤・終了状態・得点・実績を保存。
- 解いた問題の一覧から該当履歴と復習に進める。
- 同じ設定でも通常回答と復習を表示上区別。
- 実績・履歴は本人のみ。ランキングは対象外。
- 運営による権限を持つ分析閲覧は、一般参加者への公開とは分ける。
- ゲストの継続履歴、一般の練習結果のログイン後移行はTBD-06。ゲストテストの認定後付けは不可で確定。

## 10. 正答率・難易度自動判定

### FR-19 基本／復習の分離
| 回答区分 | 基本統計 | 復習統計 | 認定 |
|---|---|---|---|
| 解説前の単問回答確定 | 対象 | 対象外 | 対象外 |
| 通常練習の新規生成 | 対象 | 対象外 | 対象外 |
| 新規生成テスト・その再受験 | 対象 | 対象外 | 資格を満たすログイン利用者 |
| 履歴セットの練習し直し | 対象外 | 対象 | 対象外 |
再受験で既出の問題を解いても基本集計対象。復習モードであるかを明示的に保存し、ユーザーの既読推測だけで区分しない。
終了確定した選択済み回答のみ反映。未選択は分母から除外。不正解の選択済みは含む。変更の途中経過を複数回答として数えない。

### FR-20 難易度
| 条件 | 認定 |
|---|---|
| 基本回答10件未満 | 初級 |
| 基本回答10件以上・50％超 | 初級 |
| 同・30％超〜50％ | 中級 |
| 同・10％超〜30％ | 上級 |
| 同・0〜10％ | 専門家 |
SNS・復習回答数はサイトの最低10件に加算しない。判定は丸める前の比率を使う。
初回は基本回答10件到達時。以後は初期設定で10件増えるごとに累計基本正答率から自動更新。人間の承認待ちは不要。
その後の再判定間隔は100件などへ変更可能。最低認定件数10件と再判定間隔を分離する。
同時回答・一括終了で境界をまたいでも判定漏れや重複を防ぐ。間隔変更の適用時点・次の境界・手動例外の有無はTBD-07。

### FR-21 参加者向け正答率
- 基本回答10件未満はSNS正答率を表示、難易度は初級。
- 10件到達後はサイト基本正答率へ切替。
- 一覧・出題画面には1つの「正答率」だけ表示。出題画面では控えめなサイズ。
- SNS／サイトの由来、復習正答率、レベル別統計はこの表示へ並べない。
- SNS数値がなければ未集計等で表現する案。0％として補完しない。

### FR-22 版変更
- 新版の集計を開始し、旧版の回答を新版の分母・分子に混ぜない。
- 新版基本回答が10件に達するまでは、旧版の表示正答率・難易度を継承。
- 新版10件到達後は新版の基本正答率で表示・自動難易度判定を切り替える。
- 新規問題で旧版がない場合は通常のSNS初期表示・初級ルールを使う。
- 誤字等のどの変更を統計版の更新とするかはTBD-02。継承元の版を記録する。

## 11. 運営向け分析要件

管理者UIは別開発だが、次の情報を保存・取得可能にする。
| ID | 指標 | 定義 |
|---|---|---|
| AN-01 | 回答数 | 各回で選択済みの問題数。平均・分布 |
| AN-02 | 無回答数 | 出題数−回答数。平均・分布 |
| AN-03 | 平均点 | テスト正解数の平均。40点満点、無回答・誤答0点 |
| AN-04 | 得点率 | 正解数/出題数。テストは40固定 |
| AN-05 | 回答済み正答率 | 正解数/回答数。0回答は未定義 |
| AN-06 | 合格率 | 終了確定テストの32点以上の割合。ゲスト結果と認定合格を区別 |
| AN-07 | 時間 | 所要時間の平均・分布、時間切れ割合 |
| AN-08 | 終了状態 | 通常終了・未回答あり手動終了・時間切れ・未確定離脱等の件数 |
| AN-09 | 問題別 | 出題回数、回答数、無回答率、基本正答率、復習正答率 |
| AN-10 | レベル別 | 回答時の個人レベル別の回答数・正解数・正答率 |

### 集計条件
- 期間、練習／テスト種別、通常／復習、回答時個人レベル、ログイン有無で分けられる。
- 基本・復習を無条件に合算しない。通常のテスト平均点へ履歴復習を混ぜない。
- 時間切れは終了確定テストの平均点・合格率へ含む。未確定離脱は別枠。
- 全指標に対象件数と分子・分母を保持し、0件時は算出不可。
- 問題別の無回答率は終了確定回の未回答出題数/同じ対象の出題数とする設計案。未閲覧のまま終了した問題も出題セットに含まれたものとして記録し、閲覧の有無を区別できるとよい。
- 平均の正答率（回ごとの率の平均）と全回答の合算率は異なる。APIや画面でどちらかを明示する。基本正答率は合算の正解数/合算回答数。
- 期間抽出の基準（終了日時等）、離脱判定の期間、所要時間の切上げなどはTBD-08。

## 12. お知らせ・誤り報告

### FR-23 誤り報告
- 問題詳細・結果の各問題・解説から報告可能。
- 問題ID、問題版、該当回（存在する場合）、理由区分、自由記述を送信する想定。
- 理由候補：正解の誤り、問題文／選択肢の不備、解説／参考文献の誤り、その他。
- 送信成功・失敗を表示し、無断の二重送信を避ける。
- 運営側の受付経路、匿名報告の制限は技術相談。報告だけで問題を自動停止しない。

### FR-24 訂正告知
- 正解設定の誤り判明時は起動後最初の画面に運営からのお知らせを表示。
- 対象問題・訂正内容・掲載日時等を案内し、詳細を開ける。
- 過去のレベルアップ追加認定は行わず、合格・レベル・星の取り消しも行わない。
- 過去採点表示／問題別統計の訂正方法、既読・再表示ルールはTBD-09。

- 公開中の問題版を回答開始時に固定し、旧版を消して履歴を壊さない。
- 保存期間、削除・退会時の集計保持、バックアップ・復元はTBD-10。

## 14. 外部連携・処理境界

| 処理 | 必要な入力・出力／保証 |
|---|---|
| 問題取得 | 公開版、フィルター、ページ条件。参加者権限で管理データを返さない |
| 回開始 | モード・設定・資格確認→回ID、固定問題群、期限、開始時資格 |
| 回答保存 | 回ID・問題ID・選択ID・更新順序→保存状況。古い再送で新しい選択を上書きしない |
| 回終了 | 手動／期限→最終回答確定、採点、集計、認定。再送しても結果は一度だけ反映 |
| 履歴取得 | 本人のみ。版付きの過去問題と結果を返す |
| 統計取得 | 運営権限、フィルター、分子・分母付きの基本／復習別統計 |
| 管理連携 | 公開問題版、設定、お知らせ、報告受付。管理UIは別サイト等 |

URL・API方式・認証・DB製品は技術メンバーが決定。ブラウザの値だけを信用して得点や合格・難易度を更新しない。終了処理の一部失敗から再試行しても二重加算しない仕組みを設ける。

## 15. UI/UX・非機能要件

- 日本語、スマホ・タブレット・PCで利用可能。横スクロールに依存しない出題UI。
- キーボード操作、ラベル付き選択肢、フォーカス可視化、色以外の正誤表示、モーダルのフォーカス管理を行う。
- 残り時間を常時確認できる。終了時や認定結果は読み上げにも対応し、毎秒の過剰な通知を避ける。
- 二重押下防止、保存失敗時の再送、結果読み込み失敗時の回復導線を用意する。
- 他人の履歴へID指定でアクセスできない。認定対象テストの選択制限をサーバーでも検証する。
- 任意テキストの解説・報告・参考文献は安全に表示し、不正なスクリプト等を実行しない。
- 外部検索は許容。監視やタブ離脱検知による失格は行わない。
- 本番は永続保存を行い、ブラウザローカル保存だけで認定・全体統計を実現したとしない。
- 性能・同時利用・可用性・監視・保持期間の数値目標は技術相談。要件として未決であることを明示し、架空の保証値を設けない。
- V0段階はモックで全主要画面・状態遷移を確認し、実認証や本番集計が完了したように表示しない。
